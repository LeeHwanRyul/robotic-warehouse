## 1. 동기와 연구 질문

- **[사용자] 원래 기획(D17, D41).** 팀 라벨 없이, 같은 팀(같은 목표를 가진 agent)을 probe 응답으로 찾는다. 찾은 팀원끼리만 critic을 전이해 학습을 돕는다. 이것이 PGCT(Probe-Gated Critic Transfer)다. 중심을 "전이 적합성 발견"으로 옮기지 않는다(D41, D54, D71).
- **팀의 정의.** 같은 목표(요청 선반 집합, 배송 goal)를 가진 agent 집합이다. 개인 보상에서는 보상을 공유하지 않아도 팀이다(D81).
- **두 질문**
  - Q1 식별: 국소 정보만으로 팀원을 알아낼 수 있는가?
  - Q2 전이: 팀원의 critic을 받으면 학습이 나아지는가? 기준은 Oracle-team > IPPO, 그리고 Oracle-team > All-peer다.
- **[사용자] 메인 설정은 개인 보상이다(D81, 10-23).** 팀 보상에서는 "남의 배송으로 내 보상이 오르는가"가 곧 팀의 정의다. 그래서 보상 결합으로 팀을 찾는 것은 자명하다. 팀 보상 칸은 참조로만 쓴다.
- **목표 학회**: IJCAI 2027. 초록 1/4, 본문 1/11 AoE(HANDOFF.md 기록). 10-21에 교수님께 초판을 발표했다. 발표본 원문은 로컬 .tex에 없다. Overleaf 수정본으로 보인다(D73).

## 2. 알고리즘

### 2.1 PGCT 본체 [확인: `runs/e1f_20261018_124343_main_canonical/experiment.json`의 pgct job 설정]

1. **Probe.** 모든 agent가 같은 probe 집합을 쓴다. 학습 전에 지도와 규칙으로 만든다. 응답은 순환 상태 h=0, action mask 없이 구한다.
2. **거리.** 통신 범위 안의 이웃 i, j가 P update마다 응답을 교환한다.
   `D_ij = (1/M) Σ_m JS(π_i(·|q_m,h=0), π_j(·|q_m,h=0))` (자연로그 JS)
3. **평활.** `D̄_ij ← (1−β) D̄_ij + β D_ij`
4. **Gate.** warm-up U0 update 이후, `T̂_i = { j ∈ N_i : n_ij ≥ n_min, D̄_ij < τ }`
5. **Critic 증류.**
   `L_i = L_i^PPO + λ Σ_{j∈T̂_i} (1/|T̂_i|) (1/M_d) Σ_m ( V_i(q^d_m) − sg[V_j(q^d_m)] )²`
   T̂_i가 비면 IPPO와 같다. actor는 자기 경험으로만 학습한다.

설정값은 다음과 같다(설정 키 이름 병기).

| 기호 | 값 | 설정 키 |
|---|---|---|
| P | 5 | `probe_interval` |
| n_min | 8 | `min_probe_count` |
| β | 0.35 | `pgct_distance_ema_beta` |
| τ | 0.12 | `pgct_distance_threshold` |
| U0 | 100 | `pgct_warmup_updates` |
| λ | 0.01 | `pgct_peer_loss_coef` |
| probe 길이 | 1 | `pgct_probe_sequence_length` |
| gate 형식 | threshold | `pgct_gate_style` |

### 2.3 이론 (방법 논문 v0.3–v0.4.1, 진행 보고서 `output/pgct_progress_paper_20261023/main.tex` 4절)

- **명제 1 (정확한 부분 복원).** 분리 마진 Δ>0, 평활 오차 ε < Δ/2, τ가 그 사이에 있으면 gate가 팀을 정확히 복원한다.
- **명제 2 (추적 오차).** 갱신 사이 변화가 ρ 이하이면 `|D̄ − D| ≤ (1−β)/β · ρ`이다. β=0.35에서 계수는 1.86이다.
- **명제 3 (같은 결정 문제).** 관측 좌표에서 두 팀의 결정 문제가 같으면 최적 정책이 같아서 어떤 τ로도 팀을 가를 수 없다.
- **확장(D71).** 비교하는 양이 관측자 기준 (o,a)의 함수이면, 정책·가치·보상 예측기 모두에 명제 3이 성립한다.
- **식별 가능성의 두 원천(D71).** 이 연구의 기여 후보다.
  - (가) 목표 기하: 공통 좌표에서 팀마다 goal 위치가 다르다 → 행동·가치 probe로 가를 수 있다.
  - (나) 보상 결합: 남의 사건이 내 보상을 바꾼다(팀 보상) → 보상 결합 probe로 가를 수 있다.
- 행동 유사성은 같은 팀의 필요조건도 충분조건도 아니다. 다른 팀도 "내 goal" 기준 관측에서는 똑같이 행동할 수 있고, 같은 팀도 역할을 나누면 다르게 행동한다(T099 사용자 질문의 "스타 일꾼" 예).
- 교수님 JS convexity 질문과 명제 3·6 가정은 교수님 검토가 필요하다는 기록이 있다(D43, D44). 검토 결과는 노트에 없다.

### 2.5 보상 결합 probe (E49 정의) [확인: `output/reward_coupling_20261022/reward_coupling.py`]

- 공통 사건 e: 지도에서 정한 "goal 칸 g에서 배송"이다.
- o_i(e,t): 남이 일으킨 사건 e가 i의 시야(Chebyshev ≤ 5) 안에서 일어났고, 그 step에 i 자신은 배송·반납을 하지 않았다.
- `ρ_i(e) = mean_{t: o_i(e,t)} r_i(t) − b_i`, b_i는 사건이 없던 step의 평균 보상이다.
- `D^r_ij = mean_{e ∈ M_ij} |ρ_i(e) − ρ_j(e)|`, M_ij는 둘 다 K번 이상 본 사건이다.
- `D^r_ij < R/2`(R: 배송 보상)이면 팀원으로 본다.
- 온라인 판정(E50): 통신 범위(Chebyshev ≤ 3) 안에서 만났고 둘 다 K번 이상 봤을 때만 판정한다. 판정 전에는 전이하지 않는다.
- 팀 보상 분리 조건(스케치, 정식 증명 아님): 추정 오차 ε < R/4이면 θ=R/2가 두 팀을 가른다. 개인 보상이거나 goal 칸을 공유하면 깨진다.
- **알려진 결함.** 개인 보상에서는 모든 ρ가 0 근처라 거리가 작고 "같은 팀"으로 판정된다. "반응이 0 근처면 판정 보류" 규칙이 필요하다(D75).

### 2.6 goal 방향 축 (E54 정의) [확인: `output/probe_discriminative_20261023/goal_axis_gate.py`]

- Q*: v2 gate 48개 중 판별 probe다. 지도 BFS(운반 중에는 선반 칸 진입 불가)로 구한 최단 경로의 첫 행동 집합이 왼쪽 goal (0,10)과 오른쪽 goal (9,10)에서 겹치지 않는 probe를 고른다.
  - 모서리 배치: 13개 [1,5,6,12,15,16,23,25,27,37,41,42,47].
  - 인접 배치: 3개뿐이다.
- `s_i = (1/|Q*|) Σ_{m∈Q*} [ p_i^m(L_m) − p_i^m(R_m) ]`. L_m, R_m은 각 goal의 최적 첫 행동 집합이다.
- 부호 규칙: 부호가 같으면 팀원으로 본다. 대안은 |s_i − s_j|를 거리로 쓰는 것이다.
- 새 가정: goal 후보 칸의 위치를 지도에서 안다. 팀 라벨과 goal 배정은 쓰지 않는다. 팀이 셋 이상이면 goal 쌍마다 축이 필요하다.

## 7. 사실·관측·가설 구분 요약

**[확인]**
- trainer·환경·`examples/`는 수정하지 않았다. 새 기능은 `latent_team/`의 옵션으로 넣었다.
- 요청 대기열은 팀별이다(`request_queue_size_per_team`). 다른 팀의 요청 선반은 독점할 수 없다(D76).
- 같은 seed의 초기 가중치 hash가 run 간에 같다. seed 1의 GPU 설정 hash는 `f78ec390…`이다(E16, E19, E26, E46).
- 학습률 일정이 없다. 짧은 run은 긴 run의 앞부분(prefix)과 같은 학습이다. 다만 GPU 비결정성 때문에 bitwise 일치는 보장되지 않는다(E12, E14).
- 전이 mode는 같은 seed 재실행에서 1.4–1.6M에 갈라진다. IPPO는 2.46M까지 완전히 재현된다(E24).

**[관측]** 대부분 seed 1–2개, 단일 환경이다.
- 팀 보상 + 팀별 goal 칸이면 보상 결합 AUROC 1.00. 1–4만 step에 15쌍을 모두 맞힌다(E49, E50, E52).
- 6-agent 모서리 칸에서 goal 방향 축이 자기 goal 쪽을 .89–.96으로 가리킨다(E54).
- pen005 1M에서 한 agent가 배송의 82–99%를 한다. 독주 agent를 빼도 나머지는 배송 0–0.3/ep(E52, E53).
- 무작위 정책에서 팀당 요청 3→6→9개면 agent당 자기 팀 요청 pickup이 1.02→1.96→2.73/ep(E55).

**[가설]**
- 독주는 1M 시점의 모습이고, 2–5M에 나머지도 배울 수 있다(D78).
- 정책 JS가 실패하는 것은 팀 기준 'my goal' 채널과 GRU 기억 때문에 goal 위치가 가중치에 남지 않아서다. D77에서 냈다가 D78에서 보류했다.
- 개인 보상에서 팀원 critic은 같은 값을 추정하지 않는다(요청 경쟁). 그래서 Oracle-team이 IPPO보다 낫지 않을 수 있다(D81 위험).
- 요청 수를 늘리면 독주가 풀린다. 학습으로는 검증하지 않았다(E55).
- 4-agent run에서 goal 축이 안 나온 것은 덜 학습돼서다(E54, 미검증).

## 8. 관련 연구와 위치

- Du et al. 2025(arXiv 2511.11992): 관측 범위 이웃과 목표를 명시적으로 공유하고, 같은 목표 이웃과만 actor·critic 가중치를 평균한다. 우리 Oracle-team은 사실상 그 critic 전용 판이다. 차이는 목표를 교환하지 않고 추론한다는 점이다(D71).
- Peer Learning(Derstroff et al., AAAI 2024): bandit으로 조언자 효용을 학습한다. "전이 적합성 발견"으로 중심을 옮기면 이것과 충돌한다(D71).
- IDRL(arXiv 2210.12896): 숨은 역할 게임에서 정체성을 분류한다.
- SEAC: 다른 agent의 경험이 유익하다는 가정으로 경험을 공유한다(보상 동일 가정이 아니다). RWARE가 나온 논문이다(D76).
- SePS, MADPS(HetDPS): 파라미터 공유 집단 선택. 비교군 smoke만 했다(E15).
